Tomada de Decisão com Condicionais

(if/else e Ternário)

Tomada de Decisão

A. Conceito

A instrução if é a estrutura fundamental que permite ao JavaScript tomar decisões.

Ela avalia uma expressão entre parênteses e, se o resultado for considerado verdadeiro (truthy), executa o bloco de código associado.

No JavaScript, a avaliação converte automaticamente valores: itens como undefined, null, 0 e "" (string vazia) são tratados como falsos (falsy), enquanto qualquer outra coisa (incluindo arrays) é verdadeira.

Tomada de Decisão

A. Conceito (Continuação)

Complementando isso, a cláusula else define uma alternativa a ser executada quando a expressão falha, permitindo criar um desvio claro do fluxo do sistema.

Quando precisamos lidar com múltiplas ramificações lógicas simples, utilizamos o padrão else if, encadeando validações sem prejudicar a leitura do código.

Tomada de Decisão

Operador Ternário

Além disso, a linguagem oferece o operador condicional ternário (?:), que atua como um atalho sintático extremamente elegante para a estrutura if/else tradicional quando nosso único objetivo é retornar ou atribuir um valor.

Esta abordagem diminui o número de linhas no arquivo, facilitando a manutenção e agilizando a nossa leitura, algo essencial na dinâmica do trabalho em equipe.

Tomada de Decisão

B. Visualizando

Analogia do Fluxograma
Imaginem um fluxograma de uma portaria eletrônica. Há um bloco central de decisão em formato de losango: "O usuário enviou a senha?".

Se a seta apontar para SIM (truthy), a cancela abre (bloco de código do if). Se apontar para NÃO (falsy), o sistema emite um alerta (bloco de código do else).

O operador ternário seria a versão "Via Expressa" desse pedágio. {ver img01.png}

C. Implementação (if/else)

// Validando dados de um usuário na interface (truthy/falsy) let nomeUsuario = ""; // Falsy por ser string vazia if (nomeUsuario) { console.log("Bem-vindo, " + nomeUsuario); } else { console.log("Erro: Preencha seu nome de usuário."); }
Exemplo de Código

C. Implementação (Ternário)

// Operador Ternário para definir status de um cardápio let estoque = 5; let statusProduto = (estoque > 0) ? "Disponível": "Esgotado"; console.log("Status do Item: " + statusProduto);
Explicação Detalhada

D. Explicação linha por linha

  • let nomeUsuario = "";: Declaramos uma variável e a inicializamos com uma string vazia (considerada falsy em JS).
  • if (nomeUsuario) {: O JavaScript tenta converter a string em booleano. Como é vazia, resulta em falso e o código pula o bloco.
  • } else {: Captura a falha na condição anterior.
  • console.log(...): Exibe a mensagem de erro alertando o preenchimento.
Explicação Detalhada

D. Explicação do Ternário

  • let statusProduto = ...: Inicia a declaração de status aplicando o ternário.
  • (estoque > 0): É a nossa condição de teste.
  • ? "Disponível": Valor atribuído caso o teste acima seja verdadeiro.
  • : "Esgotado";: Valor atribuído caso o teste seja falso.

02

Roteamento de Múltiplos Caminhos

(switch)

Roteamento (Switch)

A. Conceito

A instrução switch é utilizada especificamente quando todas as nossas ramificações lógicas dependem da avaliação de uma única expressão contra vários valores diferentes.

Em vez de criar um bloco gigante e confuso cheio de else if (que torna a auditoria de código difícil), o switch calcula o valor da expressão apenas uma vez e procura um rótulo case correspondente.

Roteamento (Switch)

A. Conceito: Detalhes Técnicos

Uma característica técnica essencial é que a comparação utiliza obrigatoriamente o operador de identidade estrita (===), ou seja, não há conversão automática de tipo durante a validação.

Dentro da estrutura de roteamento do switch, a palavra-chave break desempenha um papel crítico para a estabilidade do sistema. As cláusulas case especificam apenas o ponto de partida da execução.

Roteamento (Switch)

A. Conceito: Break e Default

Se nós esquecermos o break, a execução continuará rodando ("vazará") para os casos seguintes, independentemente de coincidirem ou não.

Para lidar com valores inesperados, utilizamos a cláusula default, garantindo que sempre haverá uma saída segura para o fluxo.

Roteamento (Switch)

B. Visualizando

Analogia do PABX
Pensem num painel telefônico de uma central de atendimento (PABX). A ligação entra (expressão switch) e o sistema procura exatamente o ramal digitado (case 1, case 2).

Assim que o telefone do setor toca e é atendido, a conexão precisa ser cortada com a central (break), senão a ligação vai tocar nos outros ramais abaixo sequencialmente, virando uma confusão.

O default é a secretária eletrônica geral para quem digita um ramal inexistente. {ver img02.png}
Roteamento (Switch)

B. Visualizando

Exemplo de Código

C. Exemplo (Switch)

// Roteamento de acessos no nosso futuro Dashboard let nivelAcesso = 2; // 1: User, 2: Editor, 3: Admin switch (nivelAcesso) { case 1: console.log("Tela: Visualização de Dados"); break; case 2: console.log("Tela: Edição de Clientes Liberada"); break; case 3: console.log("Tela: Painel de Controle Total"); break; default: console.log("Erro: Nível de acesso desconhecido. Refaça o login."); }
Explicação Detalhada

D. Explicação linha por linha

  • let nivelAcesso = 2;: Simulamos o retorno de um tipo de usuário vindo do banco de dados.
  • switch (nivelAcesso) {: Inicia o painel, avaliando qual é o valor numérico exato da variável.
  • case 1:: Pergunta "nivelAcesso == 1?". Não é, então ignora.
Explicação Detalhada

D. Explicação (Continuação)

  • case 2:: Pergunta "nivelAcesso == 2?". É verdade! O fluxo entra aqui.
  • console.log(...): Imprime que a edição foi liberada.
  • break;: Fundamental. Interrompe o switch para impedir que o código caia no case 3 por acidente.
  • default:: É o "else" do switch. O que fazer se o valor for 4, 5, "dois", etc.
  • console.log(...): Mensagem de segurança por fallback.
Prática

E. Exercícios Rápidos

  • 1. Crie um switch que valide a variável diaDaSemana (1 a 7) e imprima o nome do dia.
  • 2. Remova intencionalmente o break de um case do exercício 1 e rode o código. O que aconteceu?
  • 3. O que acontece se a variável diaDaSemana receber a string "1" no lugar do número 1?
  • 4. Adicione um default para informar "Dia inválido" se passar o número 8.
  • 5. Pesquise rapidamente na IA: É possível colocar mais de um case executando a mesma linha de código (agrupamento)? Teste isso no seu VS Code.
03

Automatização com Laços de Repetição

(for e while)

Laços de Repetição

A. Conceito

Os laços de repetição (Loops) são o motor de trabalho da automação no JavaScript, sendo capazes de repetir um bloco de código incontáveis vezes enquanto uma determinada condição for avaliada como verdadeira.

O laço for é a ferramenta perfeita para cenários onde já conhecemos previamente o limite do processamento (ex: o tamanho de um array de clientes), pois consolida a criação da variável de controle, a condição e o incremento na mesma linha.

Laços de Repetição

A. Conceito: While e Cuidados

Já a estrutura while é ideal quando a repetição depende de uma regra de negócio que não tem um fim previsível, como esperar um processo de servidor terminar.

Para mantermos a eficiência da aplicação e a ética profissional (entregando performance), devemos ser rigorosos com a condição de parada. O mau uso de laços gera "loops infinitos" que travam o navegador do cliente.

Laços de Repetição

A. Conceito: Break e Continue

Para refinar esse controle de fluxo, utilizamos break para sair totalmente do laço, e continue (com ou sem Rótulos/Labels) para pular uma iteração específica que não queremos processar, poupando processamento e mantendo as diretrizes de código limpo.

Laços de Repetição

B. Visualizando

Analogia da Esteira
Pense em uma esteira de fábrica de sapatos. O laço for é o braço robótico que pinta os sapatos.

A configuração dele diz: "comece na caixa 0 (let i = 0), continue operando se houver menos de 100 caixas (i < 100), após pintar, passe para a próxima (i++)".

Se passar pela esteira um sapato com defeito, o robô recebe um aviso de continue: ele não pinta aquele sapato defeituoso, mas volta para a posição inicial para esperar o próximo imediatamente. {ver img03.png}
Laços de Repetição

B. Visualizando

Exemplo de Código

C. Implementação (For)

// Varrendo 5 registros fictícios para construir a lista do Front-end let clientes = ["Ana", "Bruno", "Carlos", "Diana", "Eduardo"]; for (let i = 0; i < clientes.length; i++) { // Regra de negócio: pular clientes cujo nome inicia com 'C' if (clientes[i].startsWith("C")) { console.log('Puxa, o(a) ${clientes[i]} está com cadastro bloqueado. Pulando... ); continue; } // Processamento pesado (simulação) console.log( Montando para: ${clientes[i]} ); }
Explicação Detalhada

D. Explicação linha por linha

  • let clientes = [...]: Array contendo nossa lista.
  • for (let i = 0;: Passo 1 - Inicialização. Começamos a contar do índice 0 (primeiro item).
  • i < clientes.length;: Passo 2 - Condição. Enquanto i for menor que 5 (tamanho do array), continue rodando.
  • i++) {: Passo 3 - Incremento. Ao final de cada ciclo, aumente o i em 1.
Explicação Detalhada

D. Explicação do Laço (Cont.)

  • if (clientes[i].startsWith("C")) {: Valida se a string na posição i começa com "C".
  • continue;: Se começar com C, aborta a iteração atual (pulou o Carlos) e volta ao topo do for somando mais 1 no i.
  • console.log(...): Só vai imprimir as pessoas que não ativaram o continue.
Prática

E. Exercícios Rápidos

  • 1. Crie um for que conte de 1 a 10 imprimindo os números.
  • 2. Modifique o exercício 1 para contar regressivamente de 10 até 1.
  • 3. Crie um while que duplique o valor de uma variável saldo = 10 até que passe de 100.
  • 4. Utilize break para parar um loop for de 1 a 20 assim que ele bater no número 13.
  • 5. Crie um array de produtos e use um laço para imprimir o nome de cada um deles.

FAQ - Dúvidas Reais

Perguntas do mundo corporativo sobre controle de fluxo.

FAQ

Pergunta 1

"Por que no switch precisamos de três iguais (===) na cabeça da gente e o if aceita dois iguais (==)?"
Resposta: Porque o switch foi projetado para verificação de Identidade Estrita, evitando falsos positivos que causam bugs difíceis de rastrear. O uso de == (com coerção de tipos) no mercado já é desencorajado por boas práticas (Clean Code), então o JavaScript nos força a ser precisos no switch.
FAQ

Pergunta 2

"Se eu posso fazer tudo com while, por que o for existe?"
Resposta: Organização. O for agrupa inicialização, verificação e incremento em uma única linha. Fazer isso no while exige escrever mais linhas e aumenta a chance de você esquecer de somar o contador, travando a aplicação com um loop infinito.
FAQ

Pergunta 3

"Eu posso colocar um if dentro de um for?"
Resposta: Sempre! Isso é o que chamamos de aninhamento. Você varre os dados com o laço de repetição e, para cada item, usa condicionais para aplicar regras de negócios específicas (como no nosso exemplo do "Carlos").
FAQ

Pergunta 4

"Usei o ChatGPT para achar um erro e ele sugeriu a função eval(), devo usar?"
Resposta: Não! O uso de eval() é desencorajado por impedir otimizações do motor JavaScript e introduzir vulnerabilidades de segurança. O bom profissional de TI avalia o código sugerido pelas IAs, garantindo a robustez do software, em vez de aplicar atalhos que comprometem a segurança (Soft Skill: Pensamento Crítico).
FAQ

Pergunta 5

"Como o operador ternário ajuda na performance de Front-end?"
Resposta: Por sua característica lógica de "curto-circuito". Apenas um dos dois caminhos possíveis (antes ou depois dos dois pontos) é de fato processado pelo interpretador, o que poupa milissegundos essenciais ao lidar com a renderização visual do DOM na web móvel.
