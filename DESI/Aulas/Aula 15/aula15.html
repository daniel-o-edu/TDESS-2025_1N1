Onde guardamos os dados: Variáveis, Tipos e Escopo

A base do armazenamento de informações no JavaScript.

Variáveis, Tipos e Escopo

A. Conceito: Tipos Comuns

Em JavaScript, lidamos com diversos tipos comuns de dados:

  • String (textos),
  • Number (números),
  • Boolean (verdadeiro/falso),

além de valores vazios como null (representa a ausência intencional de qualquer valor de objeto) e undefined (indica que algo existe mas ainda não recebeu nenhum valor).

Variáveis, Tipos e Escopo

A. Conceito: Dados Complexos e Declaração

Para organizar dados complexos, usamos estruturas como:

  • Array (listas) e
  • Object (coleções de pares chave-valor).

Para armazenar esses dados na memória, precisamos declará-los usando palavras-chave específicas. O JavaScript moderno nos oferece let e const para declaração de variáveis, substituindo o antigo var.

Variáveis, Tipos e Escopo

A. Conceito: Escopo e Segurança

A diferença principal entre eles é o escopo, ou seja, onde a variável "existe" e pode ser acessada.

let e const

Variáveis criadas com let e const possuem escopo de bloco (existem apenas dentro das chaves {} onde foram criadas).

var

O var possui escopo de função ou global, o que frequentemente causa vazamento de dados e bugs difíceis de rastrear em sistemas maiores.

Variáveis, Tipos e Escopo

A. Conceito: Mutabilidade

A escolha entre let e const define a mutabilidade da referência:

  • Nós usamos const quando o valor (ou a referência do objeto/array) não deve ser reatribuído durante a execução do script.
  • Nós usamos let quando sabemos que o valor vai mudar, como em um contador dentro de um laço de repetição.
Boas Práticas
É uma boa prática de segurança e clareza iniciar tudo como const e só mudar para let se for estritamente necessário.
Variáveis, Tipos e Escopo

B. Explicação didática: Caixas Organizadoras

Imaginem as variáveis como caixas organizadoras. O tipo de dado é o que vai dentro: uma String é um bilhete de papel, um Number é uma calculadora, um Array é uma pasta com várias divisórias e um Object é uma maleta cheia de ferramentas rotuladas.

O escopo é onde você deixa essa caixa. O let e o const são caixas que ficam trancadas dentro da sala onde você as colocou (escopo de bloco).

Variáveis, Tipos e Escopo

B. Explicação didática: Cofres e Ruas

Ninguém do corredor consegue mexer. O const é um cofre: depois que você guarda algo lá dentro, não pode trocar por outra coisa.

Já o var é como deixar a caixa no meio da rua: qualquer um que passar pode abrir, mudar o que tem dentro e bagunçar a sua vida.

Variáveis, Tipos e Escopo

Manipulando informações: Operadores

Como criar lógica, comparar e manipular nossos dados.

Operadores

A. Conceito: Aritméticos e Atribuição

Para criar lógica, precisamos comparar e manipular nossos dados utilizando operadores.

  • Temos os aritméticos (+, -, *, /, %) para cálculos matemáticos.
  • Temos os de atribuição (=, +=, -=) para guardar valores nas variáveis.
Operadores

A. Conceito: Comparação Estrita

Os operadores de comparação (>, <, >=, <=, ===, !==) servem para testar valores e sempre nos retornam um Boolean (true ou false).

Uma característica vital do JavaScript é a comparação estrita. Nós sempre utilizamos três sinais de igual (===) em vez de dois (==). O operador == compara apenas o valor, fazendo coerções de tipo perigosas (por exemplo, transformar a string "5" no número 5 escondido).

O operador === compara o valor e o tipo do dado, garantindo que "5" == 5 seja false, evitando bugs lógicos severos.

Operadores

A. Conceito: Lógicos

Por fim, utilizamos operadores lógicos (&& para E/AND, || para OU/OR, ! para NÃO/NOT) para combinar múltiplas comparações em uma única instrução de decisão.

Com eles, nós conseguimos estruturar validações complexas, como checar se um campo de formulário não está vazio E se tem a quantidade mínima de caracteres.

Operadores

B. Explicação didática: A Fábrica

Pensem nos operadores como os juízes e os trabalhadores de uma fábrica.

  • Os aritméticos são os trabalhadores de força bruta: eles cortam, somam, dividem os materiais.
  • Os de comparação são os juízes na esteira de qualidade: eles olham para duas peças e dizem "Sim, são iguais" ou "Não, essa é maior que aquela".
  • Os lógicos são os gerentes: eles dizem "A peça só passa se for da cor vermelha E (&&) tiver mais de 2kg".
Operadores

B. Explicação didática: Inspetores

Operador ==

Sobre == vs ===: == é aquele inspetor míope. Ele vê uma maçã de plástico e uma maçã real e diz que são iguais porque têm o mesmo formato.

Operador ===

=== é o inspetor rigoroso: ele vê que o formato é igual, mas o material (o tipo do dado) é diferente, então ele reprova!

Reutilizando a Lógica: Funções Utilitárias (utils.js)

Encapsulando tarefas para organizar nosso código.

Funções Utilitárias

A. Conceito: Funções e Encapsulamento

Funções são blocos de código encapsulados que executam uma tarefa específica. Em sistemas reais, nós evitamos escrever a mesma lógica de cálculo ou validação várias vezes pelo código.

Ao invés disso, nós extraímos essa lógica para funções dedicadas. Quando agrupamos funções que resolvem problemas gerais (como formatar moeda, validar um e-mail, gerar uma data), nós criamos bibliotecas utilitárias, frequentemente armazenadas em um arquivo chamado utils.js.

Funções Utilitárias

A. Conceito: O Arquivo utils.js

O arquivo utils.js (abreviação de utilities ou utilitários) é um padrão de projeto extremamente comum em desenvolvimento de software, especialmente no JavaScript.

Ele não é uma funcionalidade nativa da linguagem, mas sim uma convenção arquitetural. Basicamente, o utils.js serve como uma "caixa de ferramentas" onde você agrupa funções genéricas, independentes e reutilizáveis que são úteis em várias partes do seu projeto, mas que não pertencem a nenhuma lógica de negócio específica.

Funções Utilitárias

1. O que costuma ter dentro de um utils.js?

As funções aqui geralmente seguem o princípio de "funções puras" (o mesmo input sempre gera o mesmo output, sem efeitos colaterais).

Exemplos comuns incluem:

  • Formatação: Funções para formatar datas (ex: formatarData(data)), moedas (ex: formatarMoeda(valor)) ou strings (ex: capitalize(texto)).
  • Validação: Verificações de formato de e-mail, CPF, ou checagem de tipos (ex: isEmpty(obj)).
  • Manipulação de Arrays/Objetos: Funções auxiliares para buscar itens em listas complexas ou mesclar objetos.
  • Conversões: Transformar unidades de medida, converter objetos para JSON, etc.
Funções Utilitárias

2. Por que usar um arquivo de utilitários?

  • DRY (Don't Repeat Yourself): Evita que você escreva a mesma lógica de formatação de data em dez arquivos diferentes.
  • Manutenibilidade: Se a regra de formatação de um telefone mudar, você altera em um único lugar (utils.js) e todo o sistema é atualizado.
  • Organização: Mantém a lógica de negócio principal limpa, retirando dela os "detalhes técnicos" repetitivos.
Funções Utilitárias

3. Exemplo Prático

Imagine um projeto com um arquivo utils.js:

JavaScript // utils.js export const formatarMoeda = (valor) => { return new Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' }).format(valor); }; export const estaVazio = (valor) => { return valor === null || valor === undefined || valor === ''; };
Funções Utilitárias

3. Exemplo Prático (Uso)

Agora, em qualquer outro arquivo do projeto, você importa essas ferramentas:

JavaScript // produto.js import { formatarMoeda } from './utils.js'; const preco = 50; console.log(formatarMoeda(preco)); // R$ 50,00
Funções Utilitárias

4. Boas Práticas

Para que o utils.js não se torne um "lixão" de código desorganizado, siga estas dicas:

  • 1. Não coloque lógica de negócio: Se a função só serve para o componente Login, ela não deve estar no utils.js. Ela pertence ao próprio componente ou a um serviço de autenticação.
  • 2. Mantenha pequenas: Se o seu utils.js ficar grande demais, divida-o em arquivos temáticos (ex: dateUtils.js, stringUtils.js, validationUtils.js).
  • 3. Documente: Como essas funções são genéricas, é vital que elas tenham comentários explicando o que recebem e o que devolvem.

E. Dinâmica: A Arte do Early Return

Legibilidade de código, carga cognitiva e manutenibilidade.

Dinâmica

A Arte do Early Return

Objetivo: Desenvolver o olhar crítico sobre legibilidade de código, carga cognitiva e manutenibilidade.

Vocês devem entender que um código não serve apenas para o computador, mas principalmente para outros humanos (ou para o seu "eu" do futuro).

Cenário: Você recebeu um código legado de um sistema de e-commerce que calcula descontos. Ele funciona, mas é difícil de manter. Sua tarefa é analisar as duas propostas de implementação e decidir qual delas deve ser usada no projeto.

Dinâmica

"Opção Pirâmide" (If/Else Aninhado)

Foca em cercar o problema com camadas.

JavaScript function calcularDesconto(usuario, produto, cupom) { let desconto = 0; if (usuario.estaAtivo) { if (produto.quantidade > 0) { if (cupom.isValid) { desconto = 0.15; } else { desconto = 0.05; } } else { console.log("Erro: Produto esgotado"); desconto = 0; } } else { console.log("Erro: Usuário inativo"); desconto = 0; } return desconto; }
Dinâmica

"Opção Direta" (Early Return / Guard Clauses)

Foca em limpar o caminho e sair rápido.

JavaScript function calcularDesconto(usuario, produto, cupom) { // Cláusulas de Guarda: Saída antecipada if (!usuario.estaAtivo) return 0; if (produto.quantidade <= 0) return 0; // Lógica do Caminho Feliz if (cupom.isValid) return 0.15; return 0.05; }
Dinâmica

Instruções para a Turma

  • 1. Observação: Leiam os dois blocos para discussão dentro das equipes.
  • 2. Debater para pensar: Respondam às três perguntas abaixo e defendam a escolha técnica.
    • Pergunta 1: Qual código é mais fácil de explicar em voz alta para um colega?
    • Pergunta 2: Se precisarmos adicionar uma nova regra agora (ex: if (usuario.isBlackFriday)), qual código fica mais fácil de modificar sem quebrar o que já existe?
    • Pergunta 3: Por que a "Opção Pirâmide" pode ser considerada perigosa em projetos grandes?
Dinâmica

Entrega da Refatoração

3. Entrega: O Relatório de Refatoração.

Cada equipe deve entregar um pequeno texto contendo:

  • A Escolha Técnica: Declarar qual opção (A ou B) será adotada como padrão no projeto.
  • Justificativa "Clean Code" (Mínimo 3 pontos): Listar três razões técnicas para a escolha. Exemplo: "A Opção B reduz a profundidade do código (indentação)."

FAQ - Dúvidas Reais

Esclarecendo os pontos cruciais do JavaScript.

FAQ

Dúvidas Reais

1. Por que nós sempre usamos === em vez de == em JavaScript?
Resposta: Porque o JavaScript tenta "ajudar" convertendo tipos secretamente se você usar ==. A string "0" vira o número 0. === obriga que o valor E o tipo sejam idênticos, impedindo bugs silenciosos no sistema.
FAQ

Dúvidas Reais

2. Posso voltar a usar var se eu preferir?
Resposta: Profissionalmente, não. O var sofre de vazamento de escopo e de hoisting confuso. O mercado adotou let e const para garantir que as variáveis existam apenas onde deveriam existir (dentro do seu bloco).
FAQ

Dúvidas Reais

3. Qual a diferença entre undefined e null?
Resposta: undefined significa que a variável foi criada, mas o próprio JavaScript diz "não faço ideia do que tem aqui ainda". null é um valor proposital que o desenvolvedor atribui para dizer "esta variável está intencionalmente vazia no momento".
FAQ

Dúvidas Reais

4. Se eu criar um const Array ou Object, não posso mais mexer nele?
Resposta: Você não pode reatribuir a variável inteira (ex: meuArray = []), mas você pode modificar o conteúdo interno dela, adicionando e removendo itens (meuArray.push('novo item')). O const bloqueia a referência de memória, não os elementos filhos.
FAQ

Dúvidas Reais

5. Se a função não tiver a palavra return, o que acontece com o resultado?
Resposta: Ele se perde! A função fará os cálculos internamente, mas na hora de entregar a resposta para o sistema, ela entregará um valor undefined. É o erro mais comum para quem está começando.
